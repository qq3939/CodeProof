# M4 简历核验、掌握度、知识库、模式补全

## 1. 本阶段做了什么

简历：上传 PDF 或粘贴文本，模型抽取每个项目里的具体说法（技术、职责、指标），用户把项目对应到已分析的仓库后，逐条规划查询、用工具在代码里找证据，给出"有证据 / 部分有 / 找不到 / 与代码矛盾 / 代码中无法验证"的结论和修改建议。掌握度：每个考点用指数移动平均记录分数，按分数决定复习间隔（1、3、7、21 天），出题时优先到期和薄弱的考点。知识库：上传 Markdown 笔记，按标题切块，关键词（BM25）和向量两路检索用 RRF 融合，结果带出处。补全了"八股联系项目""简历追问""链路学习"三种模式。

## 4. 面试可能怎么问

1. **简历核验怎么避免"代码里没找到就说是假的"？** 结论分五档，"找不到"和"与代码矛盾"分开；"性能提升 30%"这类代码里看不出来的说法判"无法验证"，不算假。局限：近似调用解析和 grep 可能漏掉证据。
2. **为什么用 EMA 而不是平均分？** 平均分会被很久以前的低分拖住，看不出进步；EMA 让最近表现权重更大。局限：α=0.5 是经验值，没有用数据调过。
3. **RRF 为什么只看名次？** BM25 分数和余弦相似度量纲不同，直接相加没意义；RRF 只看名次，不用归一化。k=60 让靠后的名次也有贡献。
4. **混合检索比单一检索好在哪？** 关键词检索擅长精确术语（类名、注解），向量擅长语义相近的说法；评测里 hybrid 的 recall@5 最高（假模型下 0.944，真实模型待测）。
5. **知识库为什么按标题切块？** 笔记天然按知识点组织，按标题切能保持语义完整；超长的节再按长度切，重叠 100 字防止句子被切断。
6. **"八股联系项目"模式怎么出题？** 先从知识库检索与考点相关的笔记，把笔记和项目代码片段一起给模型，问"这个知识点在你的项目里体现在哪、和标准做法有什么不同"。
