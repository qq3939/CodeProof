# M7 泛化

## 1. 本阶段做了什么

**改动理解模式**：给一个提交范围（base..head）或公开 PR 地址，worker 拉取两个提交，解析 diff，找出被改动的方法以及调用它们的方法，生成"改了什么、影响哪些调用方、风险在哪"的题目，考核结束给出"是否理解这次改动"的结论。**MCP Server**：独立进程，在 Claude Code、Cursor 等客户端里用 `analyze_repo → start_session → answer / hint → get_report` 走完一遍考核；鉴权用设置页生成的个人 API 令牌（只存哈希、可吊销、记录最近使用时间）。

**没有做**：GitHub App 接入私有仓库，已搁置到投递实习之后；Python 仓库支持，决定不做。两项的理由见 D-017。完成标准里"在 Claude Code 里通过 MCP 完整走一遍"还要你亲自做一次（ROADMAP 的 B1-3）。

## 4. 面试可能怎么问

1. **为什么 MCP Server 不直接连数据库？** 走 HTTP 接口能复用鉴权、配额、限流，令牌可吊销（D-012）。代价是多一跳。
2. **API 令牌为什么只存哈希？** 数据库泄露时攻击者拿不到可用的令牌；和密码存储同理，但令牌本身是高熵随机串，不需要加盐慢哈希。
3. **改动影响分析的局限？** 依赖近似调用解析，反射、配置驱动的调用（如 MQ 监听）找不到；只分析 Java 文件，配置文件改动只作为上下文。
4. **PR 的 diff 为什么要用 merge-base？** PR 的 base 分支可能在 PR 创建后又有新提交，直接 diff 两个分支头会把别人的改动也算进来。
5. **接入私有仓库要考虑什么？** 用 GitHub App 的安装令牌（短期、权限可控）而不是用户的 OAuth token；克隆后的代码要按用户隔离可见性；去重不能跨用户复用私有仓库的分析结果。
6. **MCP 和普通 HTTP API 有什么区别？** MCP 定义了工具的描述、参数 schema 和调用方式，AI 客户端能自动发现并决定何时调用；底层仍然是本项目的 HTTP 接口。
