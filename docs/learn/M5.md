# M5 工程化

## 1. 本阶段做了什么

让系统能"长期、便宜、安全地"运行。**增量分析**：新提交只重新解析改动过的文件，没受影响的考点、题目和代码向量直接复用，并在快照里记录复用数量和省下的 token。**模型调用**：分强/快两档，指数退避加抖动的重试，超时，强模型失败降级到快模型，结构化输出校验失败重试。**限流和配额**：IP 每分钟请求数、每用户每日 token、并发任务数、并发会话数。**运维页**：任务队列（可重试）、按天/用户/会话的成本统计、会话 trace 回放（工具调用和模型调用的时间线）、评测记录。**安全**：沙箱、敏感文件、提示注入防护和注入样本评测、api 只读挂载仓库。

## 4. 面试可能怎么问

1. **增量分析怎么判断哪些结果能复用？** 解析按内容哈希；考点按 `topic_key` 判断其证据文件是否改动（D-008）。局限：证据之外的被调用方改了，考点可能已过时但仍被复用。
2. **重试为什么要加抖动？** 很多请求同时失败、同时按相同间隔重试，会在同一时刻再次压垮服务（惊群）；随机抖动把重试打散。
3. **哪些错误不应该重试？** 鉴权失败、参数错误这类重试也不会成功的；限流（429）和服务端错误、超时才重试。
4. **降级会带来什么问题？** 快模型质量更差，阅卷可能更不准；所以降级会记在 trace 和 llm_calls 里，可以统计降级比例。
5. **怎么防提示注入？** 不能完全防住，只能多层降低风险：数据边界和声明、转义伪造标记、工具只读且在沙箱里、模型输出不直接执行任何东西、评测集里放注入样本检查（本项目注入样本执行数为 0）。
6. **怎么知道一场考核花了多少钱、慢在哪？** 每次模型调用记 token、延迟、费用和节点名；trace 时间线能看到哪个节点慢、调了几次工具。
7. **为什么 api 要只读挂载仓库？** 最小权限（D-010）：api 面对用户请求，即使有漏洞也写不了代码目录。
