# M6 评测

## 1. 本阶段做了什么

搭好了评测体系：评测集格式（题目、回答、人工标注、简历说法、注入样本），评测运行器，以及各项指标——出题证据有效率、阅卷与人工的一致率 / Cohen's kappa / 分数 MAE / 多次判分稳定性、三种检索模式的 recall@5、简历假说法的精确率和召回率、注入样本执行数和敏感信息泄露、每场考核的 token 和费用。可以和"通用 Agent + 提示词"的基线对比。运行结果写进 `eval_runs` 表和 `docs/eval/<日期>-<评测集>-report.md`；CI 每次用假模型跑小评测集，确认流程不坏。

**还没完成**：SPEC 要求的完成标准是"用真实模型跑出的完整报告"，以及 petclinic 和 code-nest 各 20 题的人工标注数据集（技术派只测分析成本，不标注，见 D-016）。对话模型已经接上 DeepSeek，还缺人工标注；目前 `docs/eval/` 里只有假模型跑出的报告（只能说明流程正确，数字不代表真实效果）。安排见 `docs/ROADMAP.md` 阶段 3。

## 4. 面试可能怎么问

1. **你怎么证明这个系统阅卷是靠谱的？** 原理：和人工标注对比，看一致率、kappa、MAE 和多次判分稳定性。→ 本项目：评测运行器自动算这些指标。→ 局限：目前只有小样本、只跑了假模型，真实结论要等真实模型报告和更多标注。
2. **为什么要和基线比？** 不比就不知道复杂的流程（证据、要点、复判）比"一个提示词直接打分"好多少，是否值得多花的成本。
3. **检索的三种模式各有什么优缺点？** agentic（模型自己调工具）灵活但慢且贵；vector 快但对精确的类名、注解不敏感；hybrid 两者结合，recall 最高但成本最高。
4. **评测集怎么防止"考的就是训练的"？** 评测仓库和题目固定，代码按提交 SHA 锁定；提示词调整后重跑同一评测集对比。
5. **CI 里为什么跑假模型评测？** 保证评测流程本身不被改坏（格式、指标计算、报告生成）；真实模型评测成本高，手动触发。
6. **失败案例分析怎么做？** 报告里列出与人工标注分歧最大的回答、检索没召回的题、被判错的简历说法，逐条看原因（证据不足、要点写得含糊、检索词不对……）。
