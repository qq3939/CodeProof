# M8 语言扩展与 AI 应用画像

## 1. 本阶段做了什么

在只支持 Java 的基础上，2026-10-24 定稿加了三项（D-020）：

- **语言接口**：先把"一个文件解析出什么"抽成和语言无关的统一结构（D-022）；
- **Python 支持**：tree-sitter-python 符号索引，FastAPI 只抽路由和依赖注入（D-022）；
- **AI 应用画像**：用规则识别工具调用、Agent 循环、状态图、多 Agent、MCP、RAG、上下文与安全、调用工程化八类写法，外加三条风险规则（D-023）；
- **通用兜底**：其他语言跳过符号索引，由快模型根据目录、README、源码和关键词搜索挑考点，页面标明"通用模式"（D-021）。

出题和面试官的提示词也按仓库主语言填写，不再写死"Java 面试官"。

## 4. 面试可能怎么问

1. **为什么用 tree-sitter，不用 Python 自带的 ast？** 原理：ast 是解释器自己的解析器，一处语法错误整个文件失败，也只认当前版本的语法；tree-sitter 容错、多语言统一。→ 本项目：Java 和 Python 都用 tree-sitter，解析代码是纯函数，方便单测。→ 局限：只有语法树，没有类型信息，调用关系只能近似推断。
2. **不运行代码，怎么知道一个调用调的是哪个函数？** 原理：静态分析，靠声明的类型、导入和作用域推断。→ 本项目：`self.f()` 的接收者就是所在类，`x = Foo()` 记成局部变量类型，`mod.f()` 按导入别名到对应模块里找；找不到就不连，宁可漏也不乱连。→ 局限：鸭子类型、运行时赋值、装饰器包装都解析不到；本项目后端约四分之一的调用能连上仓库内的符号。
3. **加一种语言要改哪些地方？** 原理：先抽接口，再加实现，后面的逻辑不分语言。→ 本项目：写一个解析器返回 `FileIndex`，在 `PARSERS` 里登记；框架画像（如 FastAPI）单独写，输出和 Spring 一样格式的接口。Java 的测试一行没改就通过了。→ 局限：框架画像每个框架都要单独写，所以只做了 Spring 和 FastAPI。
4. **遇到不认识的语言怎么办？模型挑的考点怎么保证不是编的？** 原理：降级而不是报错；生成结果必须可验证。→ 本项目：通用兜底让快模型看目录、README、主要源码和关键词搜索结果挑考点，每个考点都要带行号，走和规则考点同一套证据校验；页面标明"通用模式"。→ 局限：只能保证引用的代码存在，不能保证理解对；考点名字不稳定，掌握度跨提交追踪差。
5. **怎么识别一个 Agent 循环和它的终止条件？会漏什么？** 原理：Agent 循环 = 反复调模型、执行模型要求的工具，直到不再要求或到上限。→ 本项目：函数里有循环语句、调了模型、处理了 `tool_calls`，就认作 Agent 循环，再找 `range(MAX_…)`、`recursion_limit` 之类的上限；`while True` 里既没 break 也没上限就报风险。→ 局限：上限写在别的函数里、用类注册工具这些写法会漏。
6. **"工具输出没隔离就拼进提示词"为什么是风险？项目里怎么防？** 原理：提示注入，外部内容里的"忽略之前的指令"会被模型当指令执行。→ 本项目：自己的代码用 `wrap_data` 把不可信内容包在分隔标记里，再加安全规则；画像里专门有一条规则找"提示词常量 + 函数返回值直接拼接"。→ 局限：规则只认直接拼接，f-string、多步拼接检测不到。
7. **AI 应用画像为什么用规则，不让模型直接读代码找？** 原理：确定性 vs 灵活性的取舍。→ 本项目：规则零成本、结果确定、能用假模型写测试，证据落在具体行上；改写成考点说明这一步再交给模型。→ 局限：换个写法就漏，规则要随框架演进维护。
8. **分析本项目自己时，检测代码会不会把自己当成 AI 用法？** 原理：自举问题，检测器的源码里满是它要检测的关键词。→ 本项目：规则优先看解析出的结构（调用、装饰器、赋值），不看原文；必须看原文的跳过注释，正则写成匹配不到自己的形式（比如向量运算符写成字符类）。用本项目后端验证过没有自报。→ 局限：这些写法比较脆，改规则时要再跑一遍本项目验证。
