# M2 出题与阅卷

## 1. 本阶段做了什么

在考点的基础上生成题库：每道题都带 2–5 个答案要点，每个要点必须引用代码证据（文件 + 行号范围），并逐条校验证据真实存在。考核会话按模式生成出题计划；每答完一题就投递一个独立的阅卷任务，阅卷模型只看题目、要点、证据代码和回答，逐要点判"命中 / 部分命中 / 未命中"，接近及格线时复判取多数。报告页展示总分、分类雷达图、逐要点结论、与代码矛盾的说法和可点开高亮的证据；分数同时写进掌握度。每次模型调用都记账。

## 4. 面试可能怎么问

1. **怎么防止模型出题时编造代码？** 原理：生成结果必须可验证。→ 本项目：每个要点必须引用文件和行号，校验行号存在、范围合理、片段里有题目提到的标识符，不合格的题丢弃重出。→ 局限：只能验证"引用的代码存在"，不能验证"解读是对的"，需要人工抽查。
2. **为什么阅卷要和面试官分开？** 原理：面试过程中模型已经"站了立场"（追问时可能被用户说服），独立阅卷更客观。→ 本项目：阅卷任务只看题目、要点、证据和完整回答。→ 局限：多一次调用的成本。
3. **怎么评估阅卷是否可靠？** 原理：和人工标注比较一致率、Cohen's kappa、分数平均绝对误差，同一回答多次判的稳定性。→ 本项目：`backend/app/eval/metrics.py`。→ 局限：标注数据目前只有小样本，真实模型的数字还没跑。
4. **Cohen's kappa 为什么比一致率好？** 它扣除了"碰巧一致"的部分：两边都总判"命中"，一致率很高但 kappa 接近 0。
5. **怎么控制成本？** 模型分档（快模型做简单判断）、每日配额、单场预算（用完自动结束）、增量分析复用题目、记账和费用页。
6. **为什么报告要等阅卷任务结束？** 阅卷是异步的；报告任务先等同一会话的阅卷任务全部结束（`_wait_grade_jobs`），否则总分会缺题。局限：某个阅卷任务失败时，报告会在超时后用已有结果生成。
7. **前端渲染模型输出要注意什么？** 模型可能被仓库里的恶意内容诱导输出 `<script>`，所以关闭 Markdown 原始 HTML 并用 DOMPurify 清洗。
