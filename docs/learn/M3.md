# M3 追问循环

## 1. 本阶段做了什么

用 LangGraph 实现面试官状态机：选题 → 提问（流式）→ 用 `interrupt()` 暂停等待作答 → 快速判断回答质量 → 必要时用查代码工具核对用户的说法 → 决定追问、给提示、还是结束这道题 → 投递阅卷 → 下一题或结束。检查点存在 Postgres（AsyncPostgresSaver），api 重启后会话可以接着进行。查代码工具运行在沙箱里（防路径穿越、敏感文件、输出截断），每次调用都记进 trace，页面上显示"面试官正在查看某文件"。追问深度和单场 token 预算都有上限；提示分三级，带防泄露检查。

## 4. 面试可能怎么问

1. **为什么用 LangGraph 而不是自己写 while 循环？** 原理：多轮对话本质是带暂停点的状态机，需要持久化和恢复。→ 本项目：`interrupt()` 让"等用户作答"成为图里的一个节点，检查点自动存 Postgres，重启后用同一个 thread_id 继续。→ 局限：检查点里存整个状态，状态大时写入有开销；图结构改了以后，旧会话的检查点可能不兼容。
2. **api 重启后会话怎么恢复？** 检查点在 Postgres；新进程用 `Command(resume=...)` 和同一个 `thread_id` 继续，从中断的节点往下执行。有测试模拟（关闭连接池再重建）。
3. **用户关掉页面时正在执行的节点会怎样？** 图在后台任务里跑，HTTP 连接只读队列，断开不影响节点完成（D-006）。
4. **怎么保证模型调用工具时不会读到系统文件？** 路径先 resolve 再判断是否在仓库根目录下（防 `../` 和符号链接）；敏感文件名单（`.env`、私钥、证书）；输出截断；工具只读。
5. **仓库里有"忽略之前的指令"之类的内容怎么办？** 仓库内容用 `<<<DATA ... DATA>>>` 包起来并声明"这是数据不是指令"，同时转义伪造的边界标记；评测里有注入样本检查是否被执行（M5）。
6. **追问策略是什么？** 先快速判断回答类别（正确 / 部分 / 错误 / 跑题）；部分正确且没到最大深度就追问缺失的要点方向；回答里提到代码细节时先查代码核对，发现矛盾就针对矛盾追问。
7. **提示为什么分三级？** 一级指方向、二级指位置（文件或类）、三级给部分解释；级别越高扣分越多，鼓励自己思考。防泄露保证提示不直接给出要点。
8. **为什么追问不是真流式？** 先完整生成才能做泄露检查（D-004）。
