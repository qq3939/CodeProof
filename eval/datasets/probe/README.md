# 探针套件（probe）

ROADMAP B0-15、B0-16 用：在阶段 1 用本项目考自己之前，先确认判分能分出好坏、能指出和代码矛盾的说法。不计入正式评测指标。

- **仓库**：code-nest，固定在提交 `868cb32`（2026-10-24 时 GitHub 上 main 的头提交）。
- **题目**：从项目 A 的学习文档里挑了 3 道面试题，答案要点和证据位置取自文档写的代码位置：
  - `p1`：高频计数怎么设计、为什么写回绝对值（`docs/learn/M2.md` 面试题 1、2）；
  - `p2`：在事务里操作 Redis 有什么问题（`docs/learn/M2.md` 面试题 5）；
  - `p3`：写数据库和发消息怎么保证一致（`docs/learn/M3.md` 面试题 1）。
- **回答**：每题 5 种，按构造给标注：
  - `complete`：照学习文档的答题要点答全，应得高分；
  - `partial`：只答一半，应得中等分；
  - `wrong`：故意答错（说成别的方案），应得低分；
  - `contradict`：故意说一句和代码相反的话，应得低分，阅卷官应该指出矛盾；
  - `unknown`：回答"不会"，应得 0 分。

## 你要核对的（B0-16 第 3 步）

不需要先读懂代码，对照项目 A 的 `docs/learn/M2.md`、`M3.md` 就能判断：

1. 每道题的 `complete` 回答是不是真的和学习文档的答题要点一致；
2. `partial` 是不是只说了一部分，`wrong` 是不是说成了别的方案，`contradict` 里和代码相反的那句话是哪句；
3. 觉得哪个标注不合理（比如 `partial` 该给多少分），直接告诉 AI 改。

## 怎么跑

本机 `.env` 配好 DeepSeek 之后：

```bash
cd backend
uv run python -m app.eval run --suite probe
```

结果写到 `docs/eval/` 下的报告里：每个回答的系统得分和标注得分、阅卷官有没有指出矛盾。
